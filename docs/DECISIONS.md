# Decision log

One line per non-obvious technical choice, with the reason. Append, never rewrite.

| Date | Decision | Why |
|---|---|---|
| 2026-07-20 | Native SwiftUI, not React Native | The magic lives in native iOS APIs (CoreNFC, App Clips, LocalAuthentication). Cross-platform wraps exactly the parts that matter, and debugging across a bridge is brutal for a beginner. |
| 2026-07-20 | Supabase over a custom backend | Row Level Security expresses the core product invariant as a database rule, so "only attendees can see this" is enforced server-side by construction. |
| 2026-07-20 | QR handshake in v1, NFC in v2 | Apple restricts iPhone NFC tag emulation to Secure Element use cases; social contact exchange doesn't qualify. Physical chips come later behind a `ConnectionMethod` protocol. |
| 2026-07-20 | Reciprocal FaceID, not scanning the other person | `LocalAuthentication` only authenticates the device's own enrolled owner and returns pass/fail. Scanning a third party would mean processing biometric data under GDPR Art. 9. |
| 2026-07-20 | Location proximity check is mandatory | Without it a QR code can be shown over a video call, faking a meeting. Proximity is the only thing that closes that hole in v1. Doubles as the passport map data source. |
| 2026-07-20 | Event photos persist after upload window closes | Expiry can always be added; deletion can never be undone. `visible_until` exists in the schema, defaulting to NULL. |
| 2026-07-20 | Light "paper" default, dark only for rituals | The palette's soul is analog-warm and a photo album is light. Dark navy is reserved for the handshake and live events so those feel ceremonial. |
| 2026-07-20 | Deployment target iOS 18.0, not Xcode's 26.2 default | Matches the stack table in CLAUDE.md and keeps the app installable on hardware back to 2018. Nothing in the roadmap needs an iOS 26-only API. |
| 2026-07-20 | Hand-rolled FNV-1a seed for stamps, not `hashValue` | Swift reseeds its standard hasher on every process launch, so `hashValue` changes between runs. A stamp's rotation and ink breaks must be fixed forever, so the hash is written by hand in `SeededRandom.swift`. |
| 2026-07-20 | Stamp drawn in a fixed 160pt space, then scaled | One implementation serves the passport grid and, later, stamp-shaped map pins. Proportions can never drift between the two. |
| 2026-07-20 | In-page mastheads instead of system navigation bars | Restyling a UIKit nav bar requires `UINavigationBarAppearance` proxies, which leaks font and colour choices out of the design system. Phase 0 has nowhere to navigate; real `NavigationStack`s return in Phase 1. |
| 2026-07-20 | Stamp fonts declared as `UIFont`, SwiftUI `Font` derived from them | Arced stamp text is laid out character by character and measuring a glyph needs a `UIFont`. Deriving one from the other means the measured font can never drift from the drawn font. |
| 2026-07-20 | No view models in Phase 0 | There is no async state to observe yet. An `@Observable` model wrapping a static array would be ceremony that teaches a pattern doing no work. They arrive with the first real service. |
| 2026-07-21 | Bundled Josefin Sans (OFL) for UI, Courier for stamps | Two faces doing opposite jobs: a cold geometric Bauhaus sans for chrome/body, and a real machine typeface (Courier, ships with iOS) for stamps/dates/timestamps so they read as struck artifacts. Static weights instanced from the official variable font with clean PostScript names, confirmed at runtime by FontAudit — the gwfh static builds were mis-named to "Thin". |
| 2026-07-21 | Display face is one constant; `lowercaseChrome` is one flag | Every UI style derives from a single `displayFace` constant, so trialling Jost*/Futura is a one-line change. Chrome case is a single bool (Bayer's all-lowercase Bauhaus alphabet) so it can be seen both ways without touching call sites. |
| 2026-07-21 | Partial `Info.plist` + `INFOPLIST_FILE`, kept outside the synced group | `UIAppFonts` can't be a build setting, so a minimal Info.plist holds only it while `GENERATE_INFOPLIST_FILE` still synthesises the rest. It lives at project-root, not inside the file-system-synchronised source folder, or the sync group copies it as a resource and collides with the Info.plist processor. |
| 2026-07-21 | Standard `TabView`, Connect as a plain tab | A raised custom centre button would forfeit VoiceOver, tap-to-scroll-to-top, iPad adaptation and standard animations. Connect is an ordinary tab; selecting it opens the dark handshake screen and stays selected, because a scan leads somewhere. |
| 2026-07-21 | Passport is one tab, three lenses | Stamps / Map / Calendar are three readings of the same collection, not three destinations. A custom underline segmented control keeps the type in Josefin and avoids a `UISegmentedControl.appearance()` global mutation. |
| 2026-07-21 | Profiles are collages, stored in relative coordinates | A profile is a self-assembled collage, not a contact card. Item positions are 0–1 fractions of the bounds and sizes are fractions of the width, so a collage composes identically on any device — absolute points would drift across screen sizes. `content` is an enum with a computed `kind`, so an item can't hold a mismatched type. Rendering only this phase; editor deferred. |
| 2026-07-21 | Reactions show who, never a count | A public like count is a popularity scoreboard — the exact mechanic InTouch positions against. Reactions name the specific friends who reacted; no aggregate number is ever shown. |
| 2026-07-21 | UI type scales with Dynamic Type; graphic-baked type stays fixed | Named UI tokens use `Font.custom(…, relativeTo:)` so text honours the user's size setting. Type inside a fixed-size graphic (stamp city/date/mark in the 160pt stamp, collage scraps sized as a fraction of width, avatar initials in a fixed circle) and the tab-bar label stay fixed — scaling them independently of their fixed container bursts its layout, and iOS gives tab bars the large-content-viewer instead. |
| 2026-07-21 | Saturated stamp-ink set added to Palette, separate from the eight muted tokens | The muted paper palette is correct, but stamps drawn in `ink` (#4E0000) read near-black — tasteful, not alive; real passport ink is bright and pools. Five saturated inks (`stampRed/Teal/Violet/Forest/Cobalt`) were added as a clearly-fenced set, for **stamps and marks only** — never paper, text or chrome. Values chosen by eye in the passport-stamp register (no source chips), so treat as tunable. |
| 2026-07-21 | Candidate display faces trialled in a throwaway DesignLab, not by editing Typography | To choose a display face you must *see* each one at real sizes — especially 11pt tab labels, where geometric faces fail. A DEBUG-only `Features/DesignLab` renders the real sample content live under a face picker + ink picker; it mirrors Typography's sizes rather than mutating the global `displayFace`, so it deletes as one folder. Candidate faces (Archivo Black + Archivo companion, Anton, Jost) bundled alongside Josefin, static weights instanced from the official variable fonts (the instancer's `…Roman-…` PostScript names rewritten clean), all confirmed at launch by FontAudit. |
| 2026-07-22 | Display face is Jost, not Josefin Sans | Josefin's small x-height went spindly at 11pt tab-label size, where a geometric face has to carry itself; Jost holds the same cold-geometric Bauhaus character with more presence at 11pt. One-line change to `displayFace`. Jost's larger x-height also let the body/label sizes bumped for Josefin be tightened back (label 13→12, body 17.5→16.5). |
| 2026-07-22 | DesignLab and the three losing font families removed | The type decision made, `Features/DesignLab` and the Archivo Black / Archivo / Anton / Josefin Sans families (and their OFL licences) were deleted, and their `UIAppFonts` / `FontAudit.expected` entries removed. Only Jost stays bundled (Courier and Bradley Hand ship with iOS). The saturated stamp inks stay in `Palette.swift`, unused, in case the brighter register returns. |
| 2026-07-22 | A post stores an array of photos from Phase 0 | `FeedPost.photos` is `[String]` (carousel-ready) even while the feed is mock, so the Instagram-style carousel didn't have to be retrofitted once `post_media` (id, storage_path, order_index) lands. Doing it now deleted the `FeedPost.Tone` colour-block placeholder in one compiler-guided pass through Collage / CollageView / FeedCardView / MockData. Numbered sample files (ski-1/ski-2) group into one post. |
| 2026-07-22 | Feed photos framed 4:5 portrait, uniform for single and carousel | The real sample photos are mostly tall portraits; a fixed short band cropped heads/peaks. One 4:5 frame for both a single photo and every carousel page keeps the feed rhythm even. A paged `TabView` has no intrinsic height, so a `Color.clear.aspectRatio(4:5)` box gives it a concrete size via `GeometryReader`. Page dots sit on a translucent `night` capsule so `paper` dots stay legible over a bright photo (snow) as well as a dark one. |
| 2026-07-22 | Reference inspiration images committed to the repo | The four study-only folders under `docs/references/` (incl. ~190 passport covers) are version-controlled as an organised, named record (`docs/references/RENAMES.md`), accepting the repo-size cost. The shipping sample photos are separate — `docs/sample-photos/` plus the asset catalogue. |
| 2026-07-22 | StampLab: a throwaway lab to develop the stamp vocabulary | The shipping StampView is one clean circle repeated — it reads as a template, and the real target is a scattered passport page of varied shapes where a stamp usually *frames a photo pinned to a city*. A DEBUG-only `Features/StampLab` (reached from Settings, deletes as one folder like the old DesignLab) develops that vocabulary to judge before wiring it in. Nine shape families are one `StampShape` enum whose single `path(in:)` serves border, photo-clip and wear alike (an inset rect gives the concentric inner rule); seeded ink wear is a `.mask` of punched holes that works on any shape; photos are framed two ways — a perforated postage card, or clipped inside the shape with the city arced in the ink margin. Ink stays muted (the standing decision) — realness comes from shape, wear and density, not colour. Not wired into the real StampView/passport. |
| 2026-07-22 | StampLab v3: shared city-stamp library, ink-only, interior ink wash | Model change: stamps are shared PER CITY (one design everyone who's been there gets), not per-person, and hold NO photo — like a real passport. Photos move behind the stamp (tapped through in map/calendar) in a later phase, so the lab drops all photo-framing and becomes pure ink. A `StampLibrary` gives ~12 cities a distinct, characterful design — its own drawn landmark (new silhouettes: Zürich tram, NY skyline, Tokyo torii, Pisa leaning tower, Amsterdam windmill; plus the earlier seven), its own shape, muted ink and a specific subtitle — plus ONE neutral generic fallback (a star + the name) for cities not yet minted. An instance (`LabStamp`) adds only date/wear/where it lands, so the same city struck twice is the same design (the page shows Zürich/London/Rome/Paris more than once). Realism fix: `InkWash` lays a seeded, blurred, blotchy ink tint across the WHOLE interior, so a stamp reads as inked paper, not a symbol on white. Arc text was rebuilt on the shipping ArcText's offset-then-rotate method (all glyphs pivot around one common centre) so they sit evenly on the curve — the earlier per-glyph `.position` drifted. Kept: muted inks, capped seeded wear, tight area-equalised sizes, display-only page. |
| 2026-07-22 | StampLab v2: equalise dominance, display-only page, readable wear | Photo stamps were dominating (bigger + full-colour) while ink stamps were pale line-art in empty space. Three fixes: (1) ink-only stamps get a SUBSTANTIAL centre — a bold drawn landmark (`Landmark` silhouettes: Big Ben, Colosseum, Opera House, Eiffel, bridge, temple, Taj), an emblem medallion, or a heavy stacked date block, varied per stamp via `LabStamp.center`; (2) sizes sit in a tight band and are AREA-equalised by shape (rendered height ÷ √aspect), so a wide rectangle and a circle cover a similar footprint and none is a centrepiece; (3) the scattered page is a display artifact — `.allowsHitTesting(false)`, no tap targets (tapping to reach photos will live in map/calendar later), which frees it to be denser while keeping every stamp mostly visible (passport-world.jpg target). Wear was also pulled back (cap ≤ 0.5, gentler mask) so even the most distressed stamp keeps its city and date. |
| 2026-07-22 | Procedural stamps scrapped entirely | After three StampLab rounds the procedurally-drawn stamps still don't read as real, so the whole approach is abandoned rather than tuned further. Deleted: `Features/StampLab`, the shipped `StampView` + `ArcText`, and the two Passport lens views that rendered stamps (`PassportStampsView`, `PassportCalendarView`). The Passport tab and its three lenses stay; the Stamps and Calendar lenses are now `EmptyStateView` "coming soon" placeholders (Map already was one). `StampView.Kind` was embedded in the `Stamp` and `TimelineEntry` models — the only real untangle — so `Stamp.kind` was dropped (the model is retained only to feed the passport/profile counts) and the now-orphaned `TimelineEntry` + its mock timeline were removed. Kept, because non-stamp code uses them: `SeededGenerator` (CollageView), `StampRing` (CollageView + EmptyStateView ghost), the Courier font + its FontAudit entries (timestamps/marks app-wide), and the saturated stamp inks in `Palette`. The passport is rebuilt next phase as a leaf-through booklet with a real world map and calendar. |
| 2026-07-22 | Passport counts model is cities + photos, not stamps | Stamps are gone, so the honest unit of the passport is now a **city** (a place you have photos) and a **photo/moment** inside it. Two small value types replace the retired `Stamp`: `PassportCity` (name, country, lat/lng) drives the map pins and the city count; `PassportEntry` (city, date) drives the calendar rows and the photo count. Coordinates are stored as plain `Double`s with a computed `coordinate`, because `CLLocationCoordinate2D` is neither `Hashable` nor `Equatable` and `ForEach`/`Set` need both. Masthead reads "N cities · M photos"; `UserProfile.stampCount` became `cityCount` (profile stat "stamps" → "cities"). `Stamp.swift` and `MockData.stamps` deleted as now-unreferenced; all fixtures stay in `MockData.swift`. |
| 2026-07-22 | Map lens muted by SwiftUI modifiers, not custom tiles | MapKit's SwiftUI `Map` can't be re-skinned to the printed-atlas palette DESIGN.md wants (no per-feature land/water colours), so the muted look is composited on top: `.mapStyle(.standard(pointsOfInterest: .excludingAll))` strips POI clutter, `.saturation(0.4)` pulls the bright green/blue out of the tiles, and a low-opacity `Color.paper` `.softLight` overlay (`.allowsHitTesting(false)`, so gestures pass through) warms it. Pins are a custom `Annotation` — a small `ink` dot ringed in `paper` with the city name as its label — not a default `Marker` balloon, so they read as struck marks. Near-black `ink` survives the desaturation, staying crisp. Default region is computed from the bounding box of all cities (1.5× padded, floored), so every pin frames on open; pinch/pan then take over (SwiftUI gives them free — we just don't disable them). Tap-through to a city's photos is deferred. |
| 2026-07-23 | Passport home is the cover/book; rotate-to-open replaces the lens picker | The Passport tab now opens on the closed cover (portrait). Rotating to landscape swings the cover open into a leaf-through two-page book (`PassportBookView`): spread 0 is identity ǀ the map (the map is absorbed here, no longer its own lens); spreads 1…N are one per city — a label ǀ a solid Bauhaus block (real collage is a later pass). The old `Stamps/Map/Calendar` `PassportLensPicker` is retired from the tab; **Calendar has no home in this design yet and is unreachable from the tab** — deliberate, revisited later. `PassportLensPicker` (and the `PassportLens` enum it carried) was fully dead after the rewire and was deleted; `PassportCalendarLens` is kept (it stands alone, no picker dependency) for when Calendar returns. |
| 2026-07-23 | App portrait-locked; passport reads physical rotation via `UIDevice.orientation`, not CoreMotion | The build settings allowed iPhone landscape, so the whole UI rotated. Locked iPhone to `UIInterfaceOrientationPortrait` (both configs) so every other tab stays portrait, then read rotation ourselves. Chose `UIDevice.current.orientation` (via `beginGeneratingDeviceOrientationNotifications` + `orientationDidChangeNotification`, in an `@Observable` `DeviceOrientationModel`) over CoreMotion because **the iOS Simulator provides no device-motion data** — a CoreMotion build couldn't be verified on the simulator, which is how we test rotation. `UIDevice.orientation` updates on the simulator, works on device, and is independent of declared interface orientations so it coexists with the portrait lock; `.faceUp/.faceDown/.unknown` are ignored, holding the last valid orientation. Because the framebuffer stays portrait, the open book is laid out at landscape size and counter-rotated (±90° from `.landscapeLeft/Right`) to read upright in the hand. |
| 2026-07-23 | New Bauhaus block palette for city pages; deterministic city→colour | City right-pages are a solid colour block until the real collage lands. Added a fenced `bauhaus*` set (`Red/Blue/Yellow/Black/Orange/Teal/Sand`) to `Palette.swift` rather than repurposing the `stamp*` inks (documented stamps-only, never chrome). A city maps to one block by a hand-rolled djb2 fold over its name's UTF8 bytes (**not** `String.hashValue`, which reseeds per launch), so a city always looks the same. |
| 2026-07-23 | Cover opens with a leading-edge 3D hinge; page turns kept plain | The cover swings open on a `rotation3DEffect` anchored at the leading edge (`axis (0,1,0)`, perspective) — the one place the animation budget is spent. Leafing between spreads is deliberately plain (an offset slide, tapped via edge zones rather than a rotation-aware drag gesture, since the book is counter-rotated) — no page-curl. |
| 2026-07-23 | Passport pages authored on a fixed 232×330 reference, scaled to fit | The design ("Passport Cover Directions") draws every page on one ID-3 reference page (88×125mm ≈ 1:1.42 → 232×330 pt). The interior is coordinate-heavy (security printing, the collage grid, the colophon rules) and re-deriving it proportionally per device is fragile, so a `PassportPage` container lays content out once at the reference size and `scaleEffect`s it to the page frame — every design measurement maps 1:1 and shares one coordinate space with the security layer. Type baked into these scaled pages uses fixed `passport*` sizes (no Dynamic Type), the existing graphic-baked-type rule. The map page is the exception: a live MapKit view can't be scale-effected, so it stays native and sized to the page. |
| 2026-07-23 | Security printing is parametric, not baked SVG | The guilloché, wave field, microprint and intaglio frame beneath the identity/city/colophon pages are computed in-code: `GuillocheRosette` is an epitrochoid `Shape` (lobes = R/r; pen offset opens the interior loops), `WaveField` tiles one cubic wave as a single stroked `Shape`, `MicroprintBand` is rotated low-opacity text, `IntaglioFrame` is nested `strokeBorder` insets. Composed in `SecurityPrinting` with a `.standard`/`.heavy` level (colophon is heavy), drawn at the design's reference opacities. `ink` is a single parameter so the UV phase can swap in a fluorescing colour. |
| 2026-07-23 | The book floats on a resting surface; cover reworked to 1c | Per the design, the closed cover and open spread float on the muted `PassportRestingSurface` (muted + `CornerVignettes`) with a margin, rounded cover corners and a soft shadow — not full-bleed. `PassportBookView` sizes each to a fitted footprint. The cover adopts 1c: a plain lowercase "passport" wordmark + uppercase holder name over the shared `PassportCoverField` (ink + diagonal wear + vignettes + grain), replacing the earlier "pass / you had to be there / int·0001" grid. `PassportBackCoverView` is the same field without the wordmark, wired as the final spread's right page (inside-back); a true full-bleed outside back cover is a deferred separate task. Holder number + MRZ are mocked in-feature (`PassportHolder`), since `UserProfile` (Core/Models) is out of scope this build. |
| 2026-07-23 | After-dark (UV) is driven by time of day, threaded via the environment | The booklet renders daylight or UV from `PassportTimeOfDay` (@Observable) — no gesture/toggle; UV is just what it looks like at night. **Placeholder boundary:** a fixed local hour (daylight 07:00–18:59, UV 19:00–06:59); real sunrise/sunset needs CoreLocation (a permission prompt + the city-level-only privacy rule) so it's deferred — `renderMode` is the single seam to swap. The mode flows down as an `EnvironmentValues.passportRenderMode`; every page/surface reads it and switches ground (paper→`uvGround`), inks and fields. Fluorescing text/marks use a shared `.fluoresce(_:)` glow; the security printing switches `ink`→`stampTeal` and brightens; photo cells go dark/non-reactive (`uvCell`) while empty collage cells glow (cobalt/violet/teal borders); a UV-only `PassportSpineSeal` (guilloché + mantra) appears across the identity spread's spine; the oxblood cover sinks toward the ground (red doesn't fluoresce). **Colophon after dark:** the heavy security printing is the loudest element by design — the cities/photos/holder counts stay calm and secondary (a public metric must never headline). Palette-compliant: UV "whites" are `Color.paper` at low opacity. |
| 2026-07-23 | City collage: outline-only empty cells, NOT solid Bauhaus blocks | The city right-page is now the auto-composed collage system (`PassportCollageView` + `CollageTemplate`): six Mondrian templates keyed by photo count (1/2/3/4/5/6+), photo cells as neutral placeholder slots (no photo model yet), and **empty cells outline-only — a 1.5px `ink` border with the paper showing through**. This reverses the earlier "empty cells become solid Bauhaus blocks" plan: the design's rendered `2c` templates use outlined empties, and solid Bauhaus fills are listed only under its own "try next," so they are **deferred**. Supersedes the 2026-07-23 Bauhaus-block entry — `PassportColourBlock` deleted, the `bauhaus*` palette tokens now unused (kept for the deferred fills). Per-city photo counts are mocked in-feature (`PassportMockPhotos`), chosen so all six templates are exercised. Named `PassportCollageView` to avoid colliding with the hand-assembled profile `CollageView` (deliberately its opposite). |
| 2026-07-23 | UV polish (P7c): spine seal removed; UV legibility floor; cover-aware gutter | Paging the whole book under UV surfaced four issues. (1) Removed the UV-only `PassportSpineSeal` (guilloché + "you had to be there" mantra) added in the 2026-07-23 after-dark decision — **reverses** that element; not liked as designed, and whether a hidden-reveal belongs at the spine is a later design call, not a guess now. (2) Non-glowing UV text (`paper.opacity(0.18–0.30)` on `uvGround`) was illegible; added a two-token floor to `Palette` — `uvFieldLabel` (`paper.opacity(0.5)`, ~5.3:1, WCAG AA) for struck labels and `uvFieldValue` (`0.6`) for routine values a step above, applied across identity/colophon/city; glowing hero fields keep their `stamp*` ink + halo (a separate visual channel) so hierarchy holds. (3) Removed the map's "tap a pin to open that city" caption (both modes) — it overlapped Apple's required Maps attribution and promised a deferred, unbuilt interaction. (4) The stray vertical line on the colophon/back-cover spread was the `spine`, drawn in `ink` (the oxblood cover colour): on that one spread the right page is *also* the oxblood cover, so the spine's red half merges into it and the centred `muted` crease is orphaned into an apparently continuous red field. Fixed by making the gutter cover-aware (`spread(bordersCover:)`) — the crease is dropped when the neighbour is the cover; the soft gradient stays as the binding shadow. |
| 2026-07-24 | City collages have no empty cells — every cell is a photo | **Supersedes both earlier calls** (solid Bauhaus blocks → outline-only empties, 2026-07-23). A city with N photos gets an N-cell template; sparse cities stay composed — the photos occupy a deliberate part of the grid and the rest is bare printed page, the security printing showing through as the composition. The empty-cell machinery is deleted (outline treatment, the UV cobalt/violet/teal border-glow cycle, the `bauhaus*` palette tokens), and the planned UV cell-glow equalization fix became moot with it. `CollageTemplate` now returns photo rects only; PRD § 4.4 and DESIGN.md § The city page updated. |
| 2026-07-24 | OPEN QUESTION — contour overprint on real photos is unverified | The collage photo slot is translucent (`uvCell.opacity(0.55)` under UV; the daylight `muted` wash always was), so the security printing runs continuously beneath the whole page per the one-object rule — real passports overprint linework across the portrait (anti-substitution), and the Swiss UV reference shows it. Verified only against empty placeholder rectangles so far. When the real photo model lands, re-check that the contour overprint on an actual photograph reads as security printing and not as noise over the image — settle it then, not now. |
| 2026-07-25 | Covers carry UV-reactive security printing — reverses "covers don't fluoresce" | **Supersedes the P7a/P7b behaviour** where the oxblood covers only sink into the night ground. That was an error against the reference, not a choice: the Swiss UV photos show the covers blazing with red contour lines and scattered marks — real passport covers carry UV-reactive printing even though their pigment doesn't fluoresce. Both covers now print the book's contour/mark vocabulary via `CoverPrinting` in `PassportCoverField` (front and back seeded separately), one-object as everywhere: tone-on-tone pale embossing by day (the real Swiss cover embosses its contours red-on-red), fluorescing red contours + gold specks after dark, drawn above the sink wash (the wash is lighting; the printing is the UV-reactive layer). |
| 2026-07-25 | OPS — full disk kills the toolchain confusingly; check headroom first | During the UV pass the data volume hit literally zero free bytes mid-edit. Every recovery path then deadlocked because each needed a few KB to start: the shell harness couldn't create its own output file, atomic file writes couldn't stage their temp file, and even `xcodebuild clean` died writing its activity log before deleting anything. Repo integrity held (atomic edit failures left no partial writes), but the session was blocked until space was freed from outside. Lesson recorded in CLAUDE.md: check `df -h /System/Volumes/Data` at session start and before builds in long sessions; a full disk presents as tools failing to launch, not as a clear disk error. |
| 2026-07-25 | UV pass principle — ONE OBJECT, TWO LIGHTING STATES; daylight changed | The governing rule of the whole UV design-lab pass: every printed element (contour terrain, registration marks, microprint, keyline, frames, spacing) exists identically in BOTH modes; UV changes only how elements are lit — hue, intensity, glow — never what exists or where it sits. Consequence, deliberately accepted: **daylight visibly changed** (new printing renders there at the subtle single-ink treatment, and the fix-2 spacing applies to both modes by definition) — this supersedes the "daylight verified unchanged" verifications in the P7a/P7b commits. The temporary design-lab gallery (`PassportDesignLab`) and all TEMP scaffolding (sample photos, frame/dim A/Bs) were removed at close; the `DebugUV` chip stays as a sanctioned permanent DEBUG-only dev tool. |
| 2026-07-25 | UV field-glow rule — the printing glows, the data stays calm | One system, no per-field accidents (canonical comment beside the floor tokens in `Palette.swift`): ALL field labels render `uvFieldLabel`, ALL values render `uvFieldValue` — both rebased onto `uvVioletText` (the cool violet-white of paper lit by blacklight) with one uniform faint halo (`uvFieldLit`) — and each page gets AT MOST ONE content hero (identity: name + photo block; city: masthead; colophon: none — its four values unified into the one Courier machine register, size and face included, because a registry page has entries, not headlines). The MRZ belongs to the machine/printing layer and fluoresces independently, locked to `stampRed` (the reference's machine zone is warm). Calm text is deliberately NOT pushed toward the hero's violet: hue is the hero's strongest channel, and paper physically fluoresces blue-white, never the ink's colour. |
| 2026-07-25 | UV security printing — contours carry the page; hue-zoned, three tiers, uneven bloom | The printing rebuilt around the Swiss UV reference's qualities, never its elements: a marching-squares topographic `ContourField` per page (seeded, launch-stable, memoized; solid minors + dotted interleave + index lines) replaced the uniform `WaveField` (deleted); Halton-scattered `RegistrationMarks`; horizontal microprint rows joined the gutter bands; every page prints its own terrain via a seed. Hue-zoned like the reference — teal/forest terrain, red machine keyline, gold microprint + marks, violet/cobalt rosette lace — with THE CONTOURS as the one loud element (round 3 demoted the frame to a single hairline, cut marks to sparse specks, and stripped the rosettes' halos after four systems shouted at once). Fluorescence blooms unevenly: a second seeded field partitions strokes into three intensity buckets cut at QUANTILES (equal page area, so no seed can band — range-based cuts produced a page-wide diagonal shadow, diagnosed by replaying the pipeline offline). The stamp register was brightened into the fluorescing range and `stampGold` added; printing runs CONTINUOUSLY beneath photo slots (translucent fills). Covers print the same vocabulary (see the cover reversal above). |
| 2026-07-25 | Collage frames — Bauhaus register, ONE colour per page; UV photo dim 0.50 | Daylight photo cells had no edge, so every slot carries a 3pt frame from the freshly-sampled `bauhaus*` register (sampled by eye from the reference poster — cerulean/gold/brick/warm-black, not the deleted first-pass guesses).
