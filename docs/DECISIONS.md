# Decision log

One line per non-obvious technical choice, with the reason. Append, never rewrite.

| Date | Decision | Why |
|---|---|---|
| 2026-07-20 | Native SwiftUI, not React Native | The magic lives in native iOS APIs (CoreNFC, App Clips, LocalAuthentication). Cross-platform wraps exactly the parts that matter, and debugging across a bridge is brutal for a beginner. |
| 2026-07-20 | Supabase over a custom backend | Row Level Security expresses the core product invariant as a database rule, so "only attendees can see this" is enforced server-side by construction. |
| 2026-07-20 | QR handshake in v1, NFC in v2 | Apple restricts iPhone NFC tag emulation to Secure Element use cases; social contact exchange doesn't qualify. Physical chips come later behind a `ConnectionMethod` protocol. |
| 2026-07-20 | Reciprocal FaceID, not scanning the other person | `LocalAuthentication` only authenticates the device's own enrolled owner and returns pass/fail. Scanning a third party would mean processing biometric data under GDPR Art. 9. |
| 2026-07-20 | Location proximity check is mandatory | Without it a QR code can be shown over a video call, faking a meeting. Proximity is the only thing that closes that hole in v1. Doubles as the passport map data source. |
| 2026-07-20 | Event photos persist after upload window closes | Expiry can always be added; deletion can never be undone. `visible_until` exists in the schema, defaulting to NULL. |
| 2026-07-20 | Light "paper" default, dark only for rituals | The palette's soul is analog-warm and a photo album is light. Dark navy is reserved for the handshake and live events so those feel ceremonial. |
| 2026-07-20 | Deployment target iOS 18.0, not Xcode's 26.2 default | Matches the stack table in CLAUDE.md and keeps the app installable on hardware back to 2018. Nothing in the roadmap needs an iOS 26-only API. |
| 2026-07-20 | Hand-rolled FNV-1a seed for stamps, not `hashValue` | Swift reseeds its standard hasher on every process launch, so `hashValue` changes between runs. A stamp's rotation and ink breaks must be fixed forever, so the hash is written by hand in `SeededRandom.swift`. |
| 2026-07-20 | Stamp drawn in a fixed 160pt space, then scaled | One implementation serves the passport grid and, later, stamp-shaped map pins. Proportions can never drift between the two. |
| 2026-07-20 | In-page mastheads instead of system navigation bars | Restyling a UIKit nav bar requires `UINavigationBarAppearance` proxies, which leaks font and colour choices out of the design system. Phase 0 has nowhere to navigate; real `NavigationStack`s return in Phase 1. |
| 2026-07-20 | Stamp fonts declared as `UIFont`, SwiftUI `Font` derived from them | Arced stamp text is laid out character by character and measuring a glyph needs a `UIFont`. Deriving one from the other means the measured font can never drift from the drawn font. |
| 2026-07-20 | No view models in Phase 0 | There is no async state to observe yet. An `@Observable` model wrapping a static array would be ceremony that teaches a pattern doing no work. They arrive with the first real service. |
| 2026-07-21 | Bundled Josefin Sans (OFL) for UI, Courier for stamps | Two faces doing opposite jobs: a cold geometric Bauhaus sans for chrome/body, and a real machine typeface (Courier, ships with iOS) for stamps/dates/timestamps so they read as struck artifacts. Static weights instanced from the official variable font with clean PostScript names, confirmed at runtime by FontAudit — the gwfh static builds were mis-named to "Thin". |
| 2026-07-21 | Display face is one constant; `lowercaseChrome` is one flag | Every UI style derives from a single `displayFace` constant, so trialling Jost*/Futura is a one-line change. Chrome case is a single bool (Bayer's all-lowercase Bauhaus alphabet) so it can be seen both ways without touching call sites. |
| 2026-07-21 | Partial `Info.plist` + `INFOPLIST_FILE`, kept outside the synced group | `UIAppFonts` can't be a build setting, so a minimal Info.plist holds only it while `GENERATE_INFOPLIST_FILE` still synthesises the rest. It lives at project-root, not inside the file-system-synchronised source folder, or the sync group copies it as a resource and collides with the Info.plist processor. |
| 2026-07-21 | Standard `TabView`, Connect as a plain tab | A raised custom centre button would forfeit VoiceOver, tap-to-scroll-to-top, iPad adaptation and standard animations. Connect is an ordinary tab; selecting it opens the dark handshake screen and stays selected, because a scan leads somewhere. |
| 2026-07-21 | Passport is one tab, three lenses | Stamps / Map / Calendar are three readings of the same collection, not three destinations. A custom underline segmented control keeps the type in Josefin and avoids a `UISegmentedControl.appearance()` global mutation. |
| 2026-07-21 | Profiles are collages, stored in relative coordinates | A profile is a self-assembled collage, not a contact card. Item positions are 0–1 fractions of the bounds and sizes are fractions of the width, so a collage composes identically on any device — absolute points would drift across screen sizes. `content` is an enum with a computed `kind`, so an item can't hold a mismatched type. Rendering only this phase; editor deferred. |
| 2026-07-21 | Reactions show who, never a count | A public like count is a popularity scoreboard — the exact mechanic InTouch positions against. Reactions name the specific friends who reacted; no aggregate number is ever shown. |
| 2026-07-21 | UI type scales with Dynamic Type; graphic-baked type stays fixed | Named UI tokens use `Font.custom(…, relativeTo:)` so text honours the user's size setting. Type inside a fixed-size graphic (stamp city/date/mark in the 160pt stamp, collage scraps sized as a fraction of width, avatar initials in a fixed circle) and the tab-bar label stay fixed — scaling them independently of their fixed container bursts its layout, and iOS gives tab bars the large-content-viewer instead. |
| 2026-07-21 | Saturated stamp-ink set added to Palette, separate from the eight muted tokens | The muted paper palette is correct, but stamps drawn in `ink` (#4E0000) read near-black — tasteful, not alive; real passport ink is bright and pools. Five saturated inks (`stampRed/Teal/Violet/Forest/Cobalt`) were added as a clearly-fenced set, for **stamps and marks only** — never paper, text or chrome. Values chosen by eye in the passport-stamp register (no source chips), so treat as tunable. |
| 2026-07-21 | Candidate display faces trialled in a throwaway DesignLab, not by editing Typography | To choose a display face you must *see* each one at real sizes — especially 11pt tab labels, where geometric faces fail. A DEBUG-only `Features/DesignLab` renders the real sample content live under a face picker + ink picker; it mirrors Typography's sizes rather than mutating the global `displayFace`, so it deletes as one folder. Candidate faces (Archivo Black + Archivo companion, Anton, Jost) bundled alongside Josefin, static weights instanced from the official variable fonts (the instancer's `…Roman-…` PostScript names rewritten clean), all confirmed at launch by FontAudit. |
| 2026-07-22 | Display face is Jost, not Josefin Sans | Josefin's small x-height went spindly at 11pt tab-label size, where a geometric face has to carry itself; Jost holds the same cold-geometric Bauhaus character with more presence at 11pt. One-line change to `displayFace`. Jost's larger x-height also let the body/label sizes bumped for Josefin be tightened back (label 13→12, body 17.5→16.5). |
| 2026-07-22 | DesignLab and the three losing font families removed | The type decision made, `Features/DesignLab` and the Archivo Black / Archivo / Anton / Josefin Sans families (and their OFL licences) were deleted, and their `UIAppFonts` / `FontAudit.expected` entries removed. Only Jost stays bundled (Courier and Bradley Hand ship with iOS). The saturated stamp inks stay in `Palette.swift`, unused, in case the brighter register returns. |
